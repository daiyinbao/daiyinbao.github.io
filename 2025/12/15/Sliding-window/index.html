滑动窗口解决分布式限流问题

2025-12-15

一.引言

1.说明

技术分享型博客，面向Java后端开发者，需要一定lua脚本经验

目标：让读者理解滑动窗口限流原理、掌握常用实现方法、并能在实际项目中落地

为什么需要滑动窗口限流？

在高并发系统中，一个接口如果没有限流策略，可能会因为短时间内大量请求导致：

  • 系统资源耗尽（CPU/内存/数据库连接）
  • 服务崩溃或请求响应延迟大
  • 安全风险，例如暴力破解登录、刷接口

因此，我们需要一种机制控制单位时间内请求量。

2.常见的限流算法

常见算法有：

  1. 固定窗口计数
  2. 滑动窗口计数（Sliding Window）
  3. 漏桶（Leaky Bucket）
  4. 令牌桶（Token Bucket）

本文重点讲滑动窗口算法

3.滑动窗口限流算法原理

滑动窗口是一种时间窗口动态统计请求数的方法，核心思想是：

  • 统计最近 N 秒内 的请求数
  • 判断请求是否超过限流阈值

本文主要讲解Redis实现（分布式） 实现限流

  • 用 Sorted Set 存储请求时间戳
  • 命令：(后面会重点讲解)
    1. ZADD key timestamp timestamp → 添加请求
    2. ZREMRANGEBYSCORE key 0 (now - window) → 删除过期请求
    3. ZCARD key → 获取当前请求数
    4. 小于阈值 → 允许请求，否则拒绝

优点：支持分布式、多实例共享计数
